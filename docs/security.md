# Security Rules

## Threat model

Protect:
- user accounts
- organization data
- Google OAuth tokens
- API keys
- business data
- reviews
- audit data
- n8n endpoints

## Authentication

Use secure session handling. Prefer httpOnly, Secure, SameSite cookies.

Never store authentication tokens in localStorage.

## Authorization

Every organization-owned resource must be authorized server-side.

Pattern:

```text
request
 -> authenticate user
 -> resolve organization membership
 -> verify resource.organization_id
 -> perform action
```

Never trust organization_id supplied by the client.

## Secrets

Never commit:
- `.env`
- API keys
- OAuth secrets
- refresh tokens
- n8n credentials
- database passwords

Use environment variables or a secret manager.

## OAuth

Store refresh tokens encrypted at rest.

Request minimum scopes.

Never expose access/refresh tokens to the browser.

## n8n security

- Do not expose public workflow URLs unnecessarily.
- Use authentication on internal callbacks.
- Use unique secrets for service-to-service calls.
- Validate webhook payloads.
- Add replay protection/idempotency for important events.
- Never put provider credentials into workflow parameters supplied by users.

## AI security

Treat model output as untrusted.

Validate:
- JSON schema
- enums
- length
- URLs
- IDs
- confidence ranges

Never execute code generated by an LLM.

Never let an LLM decide authorization.

Never let an LLM directly publish business-facing changes.

## Web crawling

- Respect robots.txt where applicable.
- Limit concurrency.
- Enforce request timeouts.
- Limit response sizes.
- Prevent SSRF against private IP ranges.
- Block localhost, link-local, metadata, and private network targets.
- Validate redirects.
- Normalize URLs.
- Limit crawl depth/pages.

## External actions

Publishing replies, changing business profile information, or modifying external data requires explicit user approval.

## Logging

Never log:
- access tokens
- refresh tokens
- API keys
- passwords
- full sensitive request bodies

Use correlation IDs instead.

## Dependency security

- pin/lock versions
- review new dependencies
- run vulnerability scanning
- minimize dependencies
